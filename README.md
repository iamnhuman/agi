# ИИзм — самостоятельный атлас AI-артистов

Сайт и админка работают без ChatGPT, OpenAI Sites, облачной базы и учётных записей.

## Два локальных адреса

- **Сайт:** http://localhost:3333
- **Админка:** http://localhost:3334

Нужен **Node.js 22.13+** (рекомендуется 24). В папке проекта:

```sh
npm ci
npm start
```

Запустите проект из корня командой `./start`. Первый запуск установит изолированный модуль Instagram и предложит импортировать активную сессию из Chrome. Затем интерфейс собирается и запускаются оба адреса. Оставьте терминал открытым: `Ctrl+C` или закрытие окна останавливает оба сервера. На macOS можно также дважды нажать `start.command` — он вызывает тот же сценарий.

Сессия Instagram хранится только локально и не попадает в Git. Проверить её можно командой `npm run instagram:status`, переподключить — `npm run instagram:connect`, удалить — `npm run instagram:disconnect`. Если cookies браузера недоступны, выполните `npm run instagram:login -- ВАШ_НИК`: пароль запрашивается интерактивно и не сохраняется.

Для разработки: `npm run dev`. Это те же порты, с обработкой исходников через Vite; после изменения кода обновите страницу. Не запускайте `dev` и `start` одновременно.

## Как пользоваться

1. Откройте админку на порту 3334.
2. Нажмите «Добавить артиста», вставьте ссылку Instagram или Telegram и нажмите «Заполнить».
3. Проверьте имя, выберите раздел, при необходимости исправьте описание, обложку и теги.
4. Нажмите «Сохранить карточку». Перейдите на сайт — карточка уже там.

Есть создание разделов, редактирование и удаление. Главный сайт поддерживает карточки, список, карту и поиск.

Все изменения атомарно сохраняются в **`data/catalog.json`**. Они переживают остановку сервера, перезапуск и пересборку. Файл отслеживается Git: его можно копировать, переносить на другой компьютер и восстанавливать из истории. Браузер не является хранилищем каталога.

Импорт получает доступные метаданные страницы. Если Instagram или Telegram их блокирует, создаётся черновик по ссылке. У публикации имя автора иногда требуется ввести вручную. Публичные аватарки Instagram сохранены в `public/avatars/` и включаются в обе сборки. Отчёт по загруженным и недоступным профилям — `data/avatar-import-report.json`. Абстрактные обложки у остальных карточек — оформление каталога, а не работы авторов.

## GitHub Pages

GitHub Pages размещает статический сайт. **Каталог работает на Pages без авторизации**, а **редактирование и импорт работают локально на порту 3334**. В публичной Pages-сборке ссылка на админку скрыта; никакие токены GitHub в браузере не нужны.

1. Загрузите этот проект в свой GitHub-репозиторий, ветка `main`.
2. В репозитории откройте **Settings → Pages → Source → GitHub Actions**.
3. Workflow `.github/workflows/pages.yml` проверит проект, соберёт каталог и опубликует его. Адрес появится в **Actions → Publish artist atlas → deploy**.
4. После редактирования в локальной админке сохраните и отправьте изменённый `data/catalog.json` в GitHub. Workflow опубликует обновления автоматически.

```sh
git add data/catalog.json
git commit -m "Update artist catalog"
git push
```

Отправка в GitHub производится вами: нажатие «Сохранить» в админке меняет локальный файл, но не выполняет `git push`.

Для ручной статической публикации:

```sh
npm run build:pages
```

Готовый каталог будет в `dist/pages/`. Относительные пути позволяют разместить его и в корне домена, и по адресу `https://username.github.io/repository/`. В эту сборку не входят сервер админки и страница редактирования.

Документация GitHub Pages: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

## Проверки и структура

```sh
npm test
npm run typecheck
npm run build
npm run build:pages
```

- `client/` — отдельные точки входа сайта и админки.
- `app/atlas.tsx`, `app/artist-map.tsx` — каталог и карта.
- `app/admin/panel.tsx` — админка.
- `server/` — локальный HTTP-сервер, сохранение, импорт.
- `data/catalog.json` — все артисты и разделы.
- `dist/local/` — сборка для двух локальных адресов.
- `dist/pages/` — статическая сборка GitHub Pages.

Оба локальных сервера слушают только `127.0.0.1`, а запись разрешена только с адреса админки. Пароль при локальном запуске не нужен. Не используйте этот локальный сервер как публичную админку через туннели: для такого размещения потребуются отдельная авторизация и серверный хостинг.

Ранее опубликованная версия Sites не изменяется этим переносом. Эта папка теперь запускается самостоятельно.

## Видеоархив

Сайт: http://localhost:3333/#videos. Админка: http://localhost:3334/#videos.

142 исходные записи сохранены в `data/catalog.json` в массиве `videos`, включая альтернативные ссылки. Таймлайн сортируется по дате публикации на YouTube / дате поста в Telegram, а не по времени сообщения со списком. Даты хранятся с источником (`dateUrl`); неизвестные не подменяются датой добавления. Ссылки на комментарии не наследуют дату родительского поста. В админке можно добавлять видео, получать метаданные по ссылке, редактировать название и дату, удалять запись. Дата, введённая вручную, помечается как указанная куратором. YouTube открывается во встроенном плеере, остальные видео — на странице источника.
